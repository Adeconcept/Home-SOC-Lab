# Why References Matter

Security investigations should be based on documented behaviour rather than assumptions.

Throughout this project, vendor documentation and industry-recognised frameworks were used to:

* Understand Windows Event IDs.
* Interpret Sysmon telemetry.
* Develop SPL searches.
* Map observations to MITRE ATT&CK.
* Validate investigation methodology.

Using authoritative sources improves both the accuracy and credibility of an investigation.

# MITRE ATT&CK Framework

## ATT&CK Enterprise Matrix

**Purpose**

Provide a standard framework for describing observed attacker techniques.

The following techniques were referenced during this project:

| Technique | Description                |
| --------- | -------------------------- |
| T1110     | Brute Force                |
| T1059.001 | PowerShell                 |
| T1071     | Application Layer Protocol |

**Important Note**

MITRE ATT&CK mappings describe behaviour that may be associated with an adversary technique.

Mapping an event to MITRE ATT&CK does **not** independently confirm malicious activity.

Throughout this project, all mappings were treated as investigative context rather than evidence of compromise.

# Best Practices Applied

The following best practices influenced the design of this project:

* Investigate before concluding.
* Correlate multiple telemetry sources.
* Document limitations transparently.
* Separate observations from conclusions.
* Support findings with evidence.
* Maintain repeatable investigation processes.

These practices improve investigation quality and reduce confirmation bias.
